# Security Policy

Phone Use can expose screen contents and control an Android device, so security
reports are treated as a priority.

## Supported versions

Security fixes are provided for the latest release. Before reporting a problem,
please verify it against the latest release or the current `main` branch when
practical.

## Reporting a vulnerability

Do not open a public issue for an unpatched vulnerability or include pairing
credentials, device data, screenshots, or other sensitive information in a
public report.

Use the repository's **Security** tab to submit a private vulnerability report.
Include the affected version, impact, reproduction steps, and any suggested
mitigation. If private reporting is unavailable, open a public issue containing
only a request for a private contact channel and no vulnerability details.

You should receive an acknowledgement within seven days. Please allow time for
investigation and a coordinated fix before public disclosure.

# 安全策略

Phone Use 能读取屏幕内容并操作 Android 设备，因此项目会优先处理安全报告。

安全修复面向最新发布版本。请勿为尚未修复的漏洞创建公开 issue，也不要在公开报告中附带配对凭证、设备数据或截图。请通过仓库的 **Security** 页面提交私密漏洞报告，说明受影响版本、影响、复现步骤和建议的缓解方式。如果私密报告不可用，请仅创建一个请求私密联系方式的公开 issue，不要写入漏洞细节。项目会尽量在七天内确认收到报告；公开披露前请为调查和协同修复预留时间。
